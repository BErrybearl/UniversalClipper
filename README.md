# 万能剪藏 · Universal Clipper

浏览器内运行的网页剪藏用户脚本，当前版本 **1.3.0 试用版**，提供点击即剪藏的图形入口和正文核对面板。保留正文、原文地址、作者、日期及必要图片；不调用 AI 服务。适配器提供专属数据源或正文选择器，未命中时采用通用提取规则。

## 安装与更新

1. 在浏览器安装 Tampermonkey 或 Violentmonkey。
2. 打开 [universal-clipper.user.js](universal-clipper.user.js)，复制全文到脚本管理器并保存。已有旧版时替换原脚本，避免重复安装。
3. 刷新需要剪藏的网页。点击剪刀图标立即提取，或使用 Alt+Shift+S；完成后在面板核对。
4. 在“正文预览”核对正文与图片，需要修改时切换“编辑内容”。选择保存格式，再点“导出剪藏”。

用户脚本仍为一个独立文件，没有新增运行时 CDN 依赖。Node.js 和测试依赖仅供本地开发，不是浏览器使用的前提。脚本匹配近乎所有网站，排除了本机页面和部分搜索页面，并只在顶层页面运行；@connect * 用于图片下载。雪球同源接口使用当前登录态。

## 入口和位置

- 点击剪刀图标直接剪藏，悬停提示“Clip · 剪藏本页”；拖动只调整位置，松开不会误剪藏。
- 拖动后保存位置，新打开或刷新的页面沿用；窗口变小时会限制在可见范围内。
- 面板“设置”中可隐藏浮动入口，并恢复图标默认位置。隐藏后仍可使用 Alt+Shift+S。
- 打开脚本管理器的菜单，可使用“剪藏本页”“查看剪藏结果”“剪藏设置”和“显示 / 隐藏浮动入口”。“查看剪藏结果”只打开当前页面已有结果，不重新提取。
- 修改后再次点击剪藏入口，会询问保留还是替换修改。重新打开查看已有结果时，建议使用“查看剪藏结果”菜单。
- 位置与显示开关按脚本保存。已经打开的其他网页，刷新后读取新设置。

脚本仍由用户触发才开始提取；进入页面只加载入口。站点生效范围与整页兜底规则沿用现有版本，后续另行确定。

## 这版怎样试用

默认保存 Markdown 和本地图片；有图片附件时下载 ZIP，解压后一起保留正文与“剪藏”图片目录。保留已有用户设置，输出格式可直接在面板底部切换。

建议先试三种页面；另外拖动图标后刷新，确认位置保留，并试一次隐藏后的菜单或快捷键入口：

1. 普通图文文章：核对标题、段落和图片，导出后断网打开，确认附件可读。
2. 评论或推荐较多的页面：确认这些内容没有混进正文。
3. 自动范围不准的页面：先在网页选中至少 20 字的正文，再点“重新剪藏”，检查是否只保存所选范围。

正文修改后重新剪藏，会先询问保留还是替换修改；收起面板不会丢失编辑内容。修改图片、滚动或接口设置后，需要重新剪藏才能导出。Markdown 修改不会同步到 HTML 快照，面板会提示。

反馈时提供网页地址，以及“缺了什么”或“多抓了什么”；图片问题可附导出文件中的表现。这些反馈用于完善常用站点规则。

## 评论和无关图文如何处理

先确定正文范围，再在副本上清理。文章主体优先于整个 main 或 body，评分使用清理后的内容，避免长评论因为字数更多而胜出。

- 明确的评论、回复、推荐、广告、侧栏和剪藏面板自身会排除；长评论也不会因超过 600 字被保留。
- 图片与标签限定在提取的正文范围内，不扫描整页后全部保存。
- 正常引用、正文中的“评论”一词、代码注释及 shareholder-analysis 等正文类名保留。
- 页面有多个候选、只能整页兜底、滚动达到上限、分页中断或图片未保存时，结果显示核对提示，并写入 Markdown 元数据。
- 自动范围不准确时，先选中需要保存的正文文字，再点“剪藏本页”或使用快捷键。至少选中 20 字；选中范围优先于站点数据源，自动滚动也会跳过。

这仍是规则提取，无法保证任意网站、任意版式都自动识别正确。遇到常用站点反复失准，应补充该站点的正文选择器和 exclude 排除选择器。不会用摘要替代原文。

## 导出与图片

| 设置 | 实际产物 |
|---|---|
| 本地图片 | 有成功下载的图片时，正文与图片打包为一个 ZIP；解压后相对路径可用 |
| base64 | 图片实际内联到 Markdown 与可选 HTML，成功内联的图片不另存附件 |
| 保留链接 | 正文保留远程地址，提示离线显示限制 |
| 仅 Markdown | MD；本地图片模式且有附件时为 ZIP |
| Markdown + HTML | 两种正文；本地图片模式且有附件时为同一个 ZIP |
| 仅 HTML | HTML；雪球专属数据源也会生成实际 HTML |

ZIP 为无压缩的标准 ZIP，内部使用 UTF-8 文件名。结构示例：

    2026-10-07-文章标题.md
    2026-10-07-文章标题.html
    剪藏/
      文章标题-img01.png

图片按二进制读取，验证响应类型；失败重试一次，超过单图上限或仍失败时保留远程链接并提示。图片编号按正文首次出现的顺序分配。

Markdown 预览中的修改会进入导出的 MD。HTML 是提取时的快照，不同步 Markdown 手动修改。HTML 清理了脚本、事件属性和可执行链接，并使用限制脚本执行的策略；图片处理结果与 Markdown 共用。未能保存的图片仍依赖原站地址，快照也因此不保证完全离线。

下载状态只说明已发起下载；浏览器是否允许下载以及文件是否落盘，仍由浏览器决定。

## 雪球数据源

优先读取页面内嵌 SNOWMAN_STATUS；没有可用内嵌数据且开启“接口翻页”时，才使用同源接口。默认关闭接口翻页。

每条结果保留真实 id、原文地址、作者、时间、互动数，以及转发地址与原文。支持秒或毫秒时间戳。多个条目共用一份文档级元数据，条目正文按小节分开，原文地址和互动数分别保留。

分页按 id 去重，受页数、条数和请求间隔限制。达到上限或请求中断会标注，不能把有限页数的结果理解为全部历史。接口设置沿用 3 页、100 条、1200 毫秒的默认值；请求带超时。实际接口和页面结构可能变化。

## 正文提取顺序

1. 用户选中的正文文字。
2. 适配器 source 专属数据源。
3. 适配器正文选择器。
4. JSON-LD 中与标题对应的文章正文。
5. 清理后的文章语义容器。
6. 清理后的段落密度评分。
7. 清理后的整页兜底，并提示核对。

内置适配器覆盖原有知乎、公众号、雪球、GitHub、MDN 等站点配置。这里表示存在配置，不代表已对各站点当前版本逐一完成实页验证。

添加适配器时建议明确域名边界：

    {
      name: '示例站点',
      hosts: ['example.com'],
      content: ['.article-body'],
      exclude: ['.related-widget', '.comment-thread'],
      meta: () => ({ author: firstText(document, ['.author']) })
    }

source 返回 { items, warnings?, coverage? }。条目建议提供 id、url、title、html（或纯文本 text）、createdAt、author、authorId；雪球相关字段还包括互动数、quoteHtml 和 retweetedStatus。通用内核不再自行拼接雪球地址。

## 开发与验证

Node.js 版本要求：^22.22.2 || ^24.15.0 || >=26.0.0。测试依赖固定为 jsdom 30.1.2，通过 package-lock.json 复现。

    npm run setup
    npm test

| 测试文件 | 检查范围 |
|---|---|
| test-core.js | 转换后的正文结构、行内连续性、YAML 字符串与文件名 |
| test-snowman.js | 执行真实适配器和完整剪藏流程，检查雪球元数据与转发原文 |
| test-xueqiu-api.js | 执行源文件中的分页函数，检查去重、上限、接口分流和错误处理 |
| test-workflow.js | 正文与评论混合、选区、图片、ZIP 校验、编辑导出、HTML、快捷键、滚动与分页提示 |
| test-ui.js | 浮动面板、输出格式、编辑保护、设置变更、复制、图片预览及失败恢复 |
| test-entry.js | 点击即剪藏、拖动防误触、位置与开关保存、隐藏恢复、菜单、编辑保护及处理中再次点击 |
| test-harness.js | 离线 DOM、GM API 和下载模拟，不加载外部页面资源 |

2026-10-07 验证：100 项自动检查通过。隔离 Edge 使用本地模拟文章和 GM API，验证正文与评论区分、选区剪藏、编辑与快捷键保护、复制、图片预览和失败提示、实际 ZIP 下载、页签显示、拖动边界及 1440×1000、390×500 布局；1.3.0 另验证真实图标点击、拖动不误触发、刷新后位置恢复、隐藏后的快捷键与菜单恢复、选区保持、键盘点击及缩小窗口；下载文件的完整性、编辑内容与附件路径校验通过。此前已验证长页滚动及解压后 HTML 的离线图片显示。尚未安装到用户现有浏览器的脚本管理器，也未逐站验证真实登录页。

开发者接口仍为 window.__universalClipper，可调用 clip()、extractContent(adapter)、findAdapter(url)、html2md(html) 和 getLastClip()。前几个接口沿用原用途，最后一个用于检查最近结果与警告。
